# Deployment topologies (the concrete layer)

Our repos manifest as **deployment instances** that realize the abstract
capabilities ([`reference-architecture.md`](./reference-architecture.md)). One
service can play several logical roles — e.g. hydrofoil realizes the query engine
*and* the embedded PDP *and* the engine PEP. The model captures **three
trust-differentiated topologies**; enforcement location and trust posture differ
across them.

## The gateway — where the platform manifests

In the olai-native topology an **Envoy gateway** (generated by trestle's
`stack-topology` crate, `olai-stack-topology`) fronts the stack. It is the
platform's **one cohesive API surface**: a documented invariant that *everything
goes through the gateway*. Envoy path-multiplexes the backends (catalog, lineage,
experiment-tracking, object stores) onto a single listener, plus a `/` catch-all
to the app; a prefix collision is a hard error. It is a **central gateway, not
per-service sidecars**.

With `ENVOY_AUTH` on, the gateway also becomes an **edge PEP** — an
`ext_authz`/Authelia forward-auth filter (fail-closed; strips client-forged
identity headers, re-adds auth-asserted ones). This is built but opt-in.

**Addressing varies by caller vantage** (in-container vs host vs in-process
desktop) — the same logical topology resolves to different URLs depending on where
the caller sits. `stack-topology` makes that a single tested model.

## The three topologies

### 1. olai-native (trusted compute) — the reference deployment
`#trusted`. The Envoy gateway is the one surface. **hydrofoil** is the trusted
query engine enforcing **full FGAC in-plan** (embedded Cedar PDP + engine PEP);
**mangrove** is the catalog + resource PIP + credential-vending PA (its Delta API
can feed **Lakekeeper** for Iceberg-REST interop, `#designed`); **breakwater** is
embedded in hydrofoil as a library; **headwaters** is the lineage/dynamic PIP;
**cedar-oci** is the PAP bundle; **SeaweedFS/Azurite** is object storage; Postgres
backs the services. Reads via **Delta** (delta-rs/delta-kernel).

### 2. external-engine (credential vending) — the FGAC bypass
`#untrusted`. mangrove vends a short-lived scoped credential to an **external,
untrusted engine** (Spark/Trino/notebook) after a *coarse* authorize check; that
engine then reads raw files directly. **Row filters and column masks are
BYPASSED** — only coarse access is enforced. Shown as an explicit edge. The
**non-vendable-governed-table guard** (refuse to vend a raw credential for a
governed table) is the `#designed` mitigation.

### 3. browser-wasm (client-side) — prototype
`#untrusted #prototype`. A client-side WASM query engine runs in the untrusted
browser. The catalog issues **signed URLs / proxies bytes** rather than vending
raw credentials — *no raw cloud secrets reach the browser*.

## What isn't modeled

`stack-topology` generates **local Docker Compose + Envoy** only. There is **no
Databricks-Apps deployment topology** — only a local `databricks-emulator-env`
env contract and Databricks-shaped URL paths at the gateway (to emulate the
Databricks edge locally). A real Databricks-Apps topology is future work.
