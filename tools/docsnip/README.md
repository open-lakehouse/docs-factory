# docsnip

Content tooling for docs-factory. Keeps the authoritative content in `content/`
consistent and agent-discoverable, without coupling to any static-site generator.

```console
$ docsnip validate       # check frontmatter (controlled vocabularies, required fields)
$ docsnip snippetcheck   # verify every snippet fence resolves to a unique source region
$ docsnip check          # CI: validate + snippetcheck
```

`docsnip` is the content-contract **validator**; it does not emit build
artifacts. `docsnip` does **not** expand snippets into the markdown — the
downstream site build resolves `file=/start=/end=` fences live via
`remark-code-snippets`. `docsnip snippetcheck` mirrors that plugin's failure
conditions so drift is caught in this repo's CI too.

Per-project `llms.txt` is generated by the **site build**
(`site/scripts/build-llmstxt.mjs`, a prebuild step) into `site/public/`, so it
re-uses `content-core` for content discovery, identity, and URL derivation
rather than re-implementing them here.
